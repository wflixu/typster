## 1. 产品概述 (Overview)

### 1.1 背景与痛点
Typst 作为 LaTeX 的现代化替代品，虽然编译速度极快且语法简洁，但目前官方及社区主要提供基于代码的编辑体验（Code-based）。对于习惯 Markdown（如 Typora）或 Word 的用户，缺乏“所见即所得”（WYSIWYG）是一个巨大的准入门槛。

### 1.2 产品目标
开发一款 macOS 本地原生应用，通过 **“混合编辑模式” (Hybrid Editing)**，将 Typst 的代码编写与实时渲染完美融合。
* **降低门槛：** 让用户像写 Markdown 一样写论文。
* **保留强大：** 对复杂 Typst 语法（函数、布局）提供代码级支持。
* **极致性能：** 利用 Rust 后端实现毫秒级增量编译与预览。

## 2. 用户画像 (Personas)

1.  **学术科研人员 (核心)**：厌倦了 LaTeX 缓慢的编译速度，希望寻找更现代的工具，但需要精准的数学公式排版。
2.  **理工科学生**：需要写作业或报告，不喜欢纯代码环境，喜欢 Typora 的简洁交互。
3.  **技术文档作者**：需要导出高质量 PDF，同时希望编辑过程直观高效。

## 3. 功能需求 (Functional Requirements)

优先级定义：P0 (必须有), P1 (应该有), P2 (可以有)。

### 3.1 编辑器核心 (Editor Core) - 基于 Tiptap

| ID | 功能名称 | 详细描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FE-01** | **基础富文本编辑** | 支持段落、多级标题 (`= `)、无序列表 (`- `)、有序列表 (`+ `)、粗体 (`*`), 斜体 (`_`) 的所见即所得编辑。 | **P0** |
| **FE-02** | **数学公式混合模式** | **核心亮点**。输入 `$` 触发公式模式。光标在公式内时显示源码（如 `$x^2$`）；光标移出后，原位渲染为 SVG 数学符号。 | **P0** |
| **FE-03** | **代码块与脚本** | 支持 Typst 代码块（```` ```typ ... ``` ````）。支持行内代码 (`` `code` ``)。 | **P0** |
| **FE-04** | **复杂结构降级处理** | 对于编辑器无法解析为富文本的复杂 Typst 语法（如自定义 `#function`，`#let` 变量定义），自动包裹为“原生代码块” (Raw Block)，仅提供语法高亮，不强求可视化。 | **P1** |
| **FE-05** | **智能粘贴** | 粘贴文本时自动转义特殊字符。 | **P2** |

### 3.2 文件与项目管理 (File & Project) - 基于 Tauri

| ID | 功能名称 | 详细描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **OS-01** | **文件读写** | 支持打开 `.typ` 文件；支持 Command+S 保存；支持文件更改的外部监听（若外部修改了文件，编辑器提示重载）。 | **P0** |
| **OS-02** | **项目/工作区** | 支持打开文件夹作为“Root”，以便正确解析相对路径的图片引用 (`#image("imgs/a.png")`)。 | **P1** |
| **OS-03** | **导出 PDF** | 调用后端 Typst 编译器导出当前文档为 PDF。 | **P0** |

### 3.3 渲染与预览 (Rendering & Preview)

| ID | 功能名称 | 详细描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **RV-01** | **实时分页预览** | 编辑器右侧（或快捷键切换）提供完整的、分页的 PDF/SVG 预览视图。 | **P0** |
| **RV-02** | **即时数学渲染** | 前端编辑器内的数学公式 SVG 需由后端 Rust 编译生成（保证与最终 PDF 一致），而非前端 MathJax 模拟。 | **P0** |
| **RV-03** | **错误提示** | 编译报错时，在编辑器对应行显示红线或 Tooltip。 | **P1** |

## 4. 系统架构与非功能需求 (Architecture & NFR)

### 4.1 架构设计
* **Frontend (UI):** Vue 3 + Tiptap (ProseMirror) + primevue。
    * 自定义 **Extension** 用于解析 Typst 语法。
    * 自定义 **NodeView** 用于实现数学公式和复杂节点的“源码/预览”切换。
    使用pnpm 构建
* **Bridge:** Tauri IPC (Commands & Events)。
* **Backend (Core):** Rust。
    * **In-Memory World:** 维护一个虚拟文件系统（Shadow File System），将前端的内存字符串作为编译源，而非每次读取磁盘。
    * **Incremental Compiler:** 利用 `comemo` 和 `typst` crate 的缓存机制，仅重算修改部分。

### 4.2 性能指标
* **输入延迟 (Typing Latency):** < 16ms (保证打字跟手，不做全量编译)。
* **公式渲染延迟:** < 100ms (光标移开数学公式后，SVG 变回来的时间)。
* **全文档预览延迟:** < 300ms (对于中等规模论文，后端增量编译的时间)。
* **安装包体积:** < 20MB (macOS DMG)。

### 4.3 安全性
* 由于 Typst 具有读取本地文件的能力 (`#read()`)，需通过 Tauri 的 `fs` scope 严格限制读写权限，仅允许访问用户打开的文件夹范围。

## 5. 交互设计细节 (UX Guidelines)

### 5.1 混合编辑状态机 (The Hybrid State Machine)
这是实现“Typora 感”的关键。对于数学公式节点 (`TypstEquationNode`)：

1.  **State: Preview (默认)**
    * 显示：`<img src="compiled_vector.svg" />`
    * 行为：不可直接编辑文本，点击整体选中。
2.  **Event: Click / Focus**
    * 动作：节点转换为 **Edit Mode**。
3.  **State: Edit**
    * 显示：`<span class="source-code">$ x^2 + y^2 $</span>` (带语法高亮)。
    * 行为：像普通文本一样编辑。
4.  **Event: Blur / Ctrl+Enter**
    * 动作：前端发送源码 -> 后端编译 -> 返回 SVG -> 切换回 **Preview Mode**。

### 5.2 快捷键 (Mac 标准)
* `Cmd + B`: 粗体
* `Cmd + I`: 斜体
* `Cmd + K`: 插入链接
* `Cmd + /`: 切换源码模式/预览模式 (全局)
* `$`: 智能触发数学公式块

## 6. 开发路线图 (Roadmap)

### Phase 1: 验证原型 (POC) - 2周
* 搭建 Tauri + Vue3 环境。
* Rust 后端实现 `compile_string_to_svg` 接口。
* Tiptap 实现最基本的文本输入和 Markdown 风格的导出 (Serializer)。
* **交付物：** 一个能打字、能导出 `.typ` 文件的文本框，右侧有一个不可交互的实时 SVG 预览。

### Phase 2: 混合编辑核心 (MVP) - 4周
* 实现 ProseMirror 自定义 Schema (Heading, List, Text)。
* 实现“数学公式”的 NodeView (点击展开，失焦渲染)。
* 实现 Rust 端的 `World` 增量编译逻辑。
* **交付物：** 类似 Typora 的数学公式编辑器，支持保存和导出 PDF。

### Phase 3: 完善与增强 (v1.0) - 4周
* 增加对 Typst 代码块 (`#`) 的支持。
* 文件系统集成（图片路径解析）。
* 错误处理与红线提示。
* UI 美化（Mac 原生风格）。

## 7. 潜在风险与应对 (Risks)

| 风险点 | 影响 | 应对策略 |
| :--- | :--- | :--- |
| **AST 转换丢失格式** | 从 Tiptap 转回 `.typ` 文件时，可能会丢失用户原来的换行习惯或注释。 | **策略：Opinionated Formatter**。明确告知用户，编辑器会强制格式化代码（类似 Prettier），不保证 100% 字符级还原，但保证语义一致。 |
| **Typst 语法过于复杂** | 用户写了极复杂的脚本，Tiptap 无法解析。 | **策略：Fallback 机制**。任何解析失败的段落，自动降级为纯文本代码块展示，保证内容不丢失，只损失可视化特性。 |
