## 🛡️ 防护的攻击类型

### 1. **路径穿越攻击 (Path Traversal)**

**阻止的模式**:
```
../           - Unix 风格向上遍历
..\           - Windows 风格向上遍历
%2e%2e        - URL 编码的 ..
%252e         - 双重编码
..%2f         - 混合编码
..%5c         - Windows 混合编码
%2e%2e%2f     - 完整 URL 编码
%2e%2e%5c     - Windows URL 编码
```

### 2. **系统目录访问保护**

**阻止访问**:
- `/etc/` - 系统配置目录
- `/sys/` - 内核接口
- `/proc/` - 进程信息
- `/dev/` - 设备文件
- `/root/` - 超级用户目录
- `~/.ssh/` - SSH 密钥
- `~/.gnupg/` - GPG 密钥

### 3. **文件类型限制**

**允许的文件类型** (白名单):
- `.typ` - Typst 源文件
- `.md` - Markdown 文档
- `.txt` - 纯文本
- `.toml` - 配置文件
- `.json` - JSON 数据
- `.svg`, `.png`, `.jpg`, `.jpeg` - 图片
- `.pdf` - PDF 文档

**拒绝的危险类型**:
- `.exe`, `.sh`, `.bat` - 可执行文件
- `.dll`, `.so` - 动态库
- `.sys`, `.drv` - 驱动程序

## 🔒 安全架构

### 多层防御策略

```
┌─────────────────────────────────────────────────┐
│                  用户输入                        │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│           前端安全验证 (TypeScript)              │
│  • 路径穿越检测                                   │
│  • 文件类型验证                                   │
│  • 项目边界检查                                   │
└──────────────────┬──────────────────────────────┘
                   │ (阻止则返回错误)
                   ▼
┌─────────────────────────────────────────────────┐
│          IPC 通信 (Tauri Bridge)                │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│           后端安全验证 (Rust)                     │
│  • 二次路径穿越检测                               │
│  • 系统目录访问阻止                               │
│  • 统一错误处理                                   │
└──────────────────┬──────────────────────────────┘
                   │ (阻止则返回错误)
                   ▼
┌─────────────────────────────────────────────────┐
│              文件系统操作                        │
└─────────────────────────────────────────────────┘
```

### 响应流程

**检测到攻击时**:
1. 立即阻止操作
2. 记录安全事件 (console.error)
3. 返回用户友好的错误消息
4. 不执行任何文件操作
